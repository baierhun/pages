Selection · AP 2.1–2.2

Boolean expressions make decisions

Operator Meaning
== / != Equal / not equal
< / > Less / greater
<= / >= Less / greater or equal 
int score = 82;
boolean passing = score >= 65;  // true
boolean perfect = score == 100; // false
boolean even = score % 2 == 0;  // true
An expression such as score >= 65 evaluates to a primitive boolean: true or false.
Selection · AP 2.2

Equality depends on the type

int a = 7;
int b = 7;
System.out.println(a == b); // true

String s = new String("Java");
String t = new String("Java");
System.out.println(s == t);      // false
System.out.println(s.equals(t)); // true
  • == compares primitive values.
  • For objects, == compares references: do both refer to the same object?
  • For Strings, .equals() compares character content.
Use == null to test whether a reference is null. Calling a method on null causes an exception.
Selection · AP 2.3

One decision, several possible paths

if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
} else {
    grade = "Below B";
}
  • Check conditions from top to bottom.
  • Run the first matching branch.
  • Skip the remaining branches in that chain.
  • The else runs when every earlier condition is false.
With overlapping ranges, put the more restrictive test first. Here, 95 must reach the A branch before the B branch.
Selection · AP 2.3

Separate if statements can both run

Two independent decisions

int x = 8;
if (x > 5) {
    System.out.print("A");
}
if (x > 0) {
    System.out.print("B");
}

One connected decision

int x = 8;
if (x > 5) {
    System.out.print("A");
} else if (x > 0) {
    System.out.print("B");
}
Reveal answer
Left: AB. Right: A. The second condition on the right is skipped.
Selection · AP 2.4

Nested decisions depend on outer tests

if (hasTicket) {
    if (age >= 13) {
        System.out.print("Enter");
    } else {
        System.out.print("Bring an adult");
    }
} else {
    System.out.print("Buy a ticket");
}
  • The inner decision runs only if hasTicket is true.
  • Without braces, an else belongs to the nearest unmatched if.
  • Braces make the intended grouping clear.
Check: what prints when hasTicket is false and age is 15?
Reveal answer
Buy a ticket. The inner condition is never evaluated.
Boolean logic · AP 2.5

AND, OR, and NOT

a b a && b a || b !a
true true true true false
true false false true false
false true false true true
false false false false true
&& needs both sides true. || needs at least one side true. ! reverses one Boolean value.

Useful precedence: !, arithmetic, comparisons, &&, then ||. Use parentheses to make grouping explicit.

Boolean logic · AP 2.5

Short-circuit evaluation can skip work

int count = 0;
boolean ok = count != 0
             && 24 / count > 3;
// false; division is skipped

String name = null;
boolean named = name != null
                && name.length() > 0;
// false; length() is skipped
  • &&: a false left operand determines the result.
  • ||: a true left operand determines the result.
  • Java evaluates from left to right.
  • Place a safety check before the operation it protects.
Reversing the operands in either example attempts the unsafe operation first.
Boolean logic · AP 2.6

De Morgan’s laws negate a group

!(a && b)
is equivalent to
!a || !b
!(a || b)
is equivalent to
!a && !b
!(x >= 10 && x <= 20)
// equivalent to:
x < 10 || x > 20

!(ready || done)
// equivalent to:
!ready && !done
Negate each operand and swap AND with OR. Negating < gives >=; negating == gives !=.
Selection check

Are these expressions equivalent?

A: !(x < 4 || x >= 10)
B: x >= 4 && x < 10
C: x > 4 && x <= 10

Which pair is equivalent? Use a boundary value to show why the third expression differs.

Reveal answer
A and B. De Morgan’s law gives x >= 4 && x < 10. At x = 4, A and B are true, but C is false. At x = 10, C is true, but A and B are false.
Iteration · AP 2.7

A while loop checks before each pass

int n = 2;              // initialize
while (n <= 8) {        // test
    System.out.print(n + " ");
    n += 3;            // update
}

What prints? What is n after the loop?

  • Initialize before entering the loop.
  • Test before every iteration, including the first.
  • Run the body only when the test is true.
  • Update so the loop can eventually stop.
A while loop may execute zero times.
Reveal answer
Output: 2 5 8 . Final n: 11. The final check, 11 <= 8, is false.
Iteration · AP 2.8

A for loop groups the control steps

for (int i = 0; i < 4; i++) {
    System.out.print(i + " ");
}
Step When it runs
int i = 0 Once, before the first test
i < 4 Before each iteration
Loop body Whenever the test is true
i++ After each completed iteration
Output: 0 1 2 3 . The variable i declared in the header is out of scope after the loop.
Iteration · AP 2.7–2.8

The same repetition in two forms

for

for (int k = 3; k <= 12; k += 3) {
    System.out.print(k + " ");
}

while

int k = 3;
while (k <= 12) {
    System.out.print(k + " ");
    k += 3;
}
Both print 3 6 9 12 . Preserve the initialization, condition, body, and update when converting.

A for loop often fits counting. A while loop often fits repetition until some changing state reaches a goal.

Iteration · Tracing

A trace table makes state visible

int total = 0;
for (int k = 1; k <= 4; k++) {
    total += k;

k at test Condition total after body

The body runs 4 times. The condition is evaluated 5 times. Always include the final failed condition check.
Iteration · Boundaries

Off-by-one errors start at the edges

Loop header Values of i Body executions
i = 0; i < 5; i++ 0, 1, 2, 3, 4 5
i = 0; i <= 5; i++ 0, 1, 2, 3, 4, 5 6
i = 5; i > 0; i-- 5, 4, 3, 2, 1 5
i = 2; i < 10; i += 3 2, 5, 8 3
For a non-unit step, list the actual values or count the arithmetic progression. Test zero iterations, one iteration, and the endpoint.
Iteration · Debugging

Three common loop errors


// 1. Empty loop body
for (int i = 0; i < 5; i++);
{
    System.out.print("Hi");
}


// 2. No progress
int n = 3;
while (n > 0) {
    System.out.print(n);
}
  • The stray semicolon is an empty statement: the loop repeats it, then the block prints Hi once.
  • The while loop never changes n, so it runs forever.
  • A third trap: resetting an accumulator inside the loop loses the earlier total.
A loop can also miss its stopping value: n != 0 with steps of 2 may never reach 0.
Algorithms · AP 2.9

Counters and accumulators track results

int count = 0;
int total = 0;
for (int n = 1; n <= 10; n++) {
    if (n % 3 == 0) {
        count++;
        total += n;
    }
}
  • A counter records how many values match.
  • An accumulator combines matching values.
  • Initialize a sum to 0. Initialize a product to 1.

What are count and total after this loop?

Reveal answer
Matching values: 3, 6, 9. count = 3 and total = 18.
Algorithms · AP 2.9

Processing a number one digit at a time

int number = 5072;
int sum = 0;
while (number > 0) {
    int digit = number % 10;
    sum += digit;
    number /= 10;
}
number before digit sum after
5072 2 2
507 7 9
50 0 9
5 5 14
For a nonnegative integer, % 10 extracts the last digit and integer division by 10 removes it. Input 0 produces sum 0 without entering the loop.
Algorithms · AP 2.9

Different questions need different state

Goal State and update Important boundary
Average Track sum and count; use (double) sum / count. Handle count 0 before dividing.
Minimum / maximum Start with a valid first value; replace when a better value appears. Handle an empty input separately.
Divisibility / factors Test number % candidate == 0. A divisor cannot be 0.
Any match / every match Track whether a match or failure has appeared. Decide what an empty input means.
Frequency of a condition Increment only when the condition is true. Initialize the count before the loop.
An initial maximum of 0 fails when every input is negative. Choose initial values that fit the input domain.
String algorithms · AP 2.10

String positions begin at zero

String word = "LEVEL";
int count = 0;
for (int i = 0; i < word.length(); i++) {
    String letter = word.substring(i, i + 1);
    if (letter.equals("E")) {
        count++;
    }
}
  • Valid character indices: 0 through length() - 1.
  • substring(start, end) includes start and excludes end.
  • substring(i, i + 1) gives one character as a String.
  • This loop counts 2 occurrences of "E".
The empty String has length 0, so this traversal runs zero times.
String algorithms · AP 2.10

Building a new String

String text = "robot";
String reversed = "";
for (int i = text.length() - 1;
     i >= 0; i--) {
    reversed += text.substring(i, i + 1);
}

Other common patterns

  • Filter: append only characters that meet a condition.
  • Search: look for a character or substring.
  • Palindrome: compare the original String with its reverse.
Strings are immutable. An operation creates a new String value; assignment stores the new reference.
Reveal answer
reversed becomes "tobor". The original text stays "robot".
Nested iteration · AP 2.11

The inner loop restarts each time

for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 4; col++) {
        System.out.print("*");
    }
    System.out.println();
}

Output

****
****
****
  • 3 outer iterations.
  • 4 inner iterations for each row.
  • 12 star prints and 3 newline prints.
An inner-loop variable declared in its header is initialized again each time execution reaches that inner loop.
Nested iteration · AP 2.11

Dependent bounds change the total

int count = 0;
for (int row = 1; row <= 4; row++) {
    for (int col = 1; col <= row; col++) {
        count++;
    }
}
row Inner iterations
1 1
2 2
3 3
4 4
Reveal answer
count = 1 + 2 + 3 + 4 = 10. With n rows, the total is n(n + 1) / 2. It is not 4 × 4 because the inner bound changes.
Runtime · AP 2.12

Count operations as the input grows

Pattern Body executions If n doubles
One pass from 0 to n − 1 n About 2× as many
Two separate passes of n each 2n About 2× as many
Nested loops, n by n n² About 4× as many
Inner bounds 1, 2, …, n n(n + 1) / 2 Approaches 4× as many
Repeated positive integer halving About log₂(n) About one extra iteration
Compare counts of a stated operation under the same assumptions. Elapsed time also depends on the operations, hardware, and input.
Iteration check

What does this loop compute?

int n = 1;
int total = 0;
while (n < 10) {
    if (n % 2 != 0) {
        total += n;
    }
    n++;
}

Find the final total, the final n, and the number of body executions.

Reveal answer
total = 25 from 1 + 3 + 5 + 7 + 9. Final n = 10. The body runs 9 times, and the condition is checked 10 times.
Recursion · AP 4.16

A recursive method calls itself

public static int sumTo(int n) {
    if (n == 0) {
        return 0;      // base case
    }
    return n + sumTo(n - 1); // recursive call
}
  • The base case returns without another recursive call.
  • The recursive call solves a smaller version of the problem.
  • Each call has its own parameters and local variables.
  • For this method, assume n >= 0. Each call moves toward 0.
AP Topic 4.16 focuses on determining recursive results and behavior. Writing recursive code is outside the AP course and exam scope.
Recursion · Call trace

Calls pause until a result returns

sumTo(3)
= 3 + sumTo(2)
= 3 + (2 + sumTo(1))
= 3 + (2 + (1 + sumTo(0)))
= 3 + (2 + (1 + 0))
= 6
Step through sumTo(3)

There are 4 calls in total, including the base case. Each waiting call retains its own value of n.
Recursion · Output order

Before and after the recursive call

public static void show(int n) {
    if (n == 0) {
        return;
    }
    System.out.print(n + " ");
    show(n - 1);
    System.out.print(n + " ");
}

What prints for show(3)?

  • The first print runs while calls move toward the base case.
  • The second print runs as calls return.
  • A return resumes the caller immediately after its recursive call.
Reveal answer
3 2 1 1 2 3 . The base case prints nothing. The waiting calls finish in the order n = 1, then 2, then 3.
Recursion · AP 4.16

Repeated calls count separately

public static int grow(int n) {
    if (n <= 1) {
        return 1;
    }
    return grow(n - 1) + grow(n - 1);
}

What does grow(3) return? How many method calls occur, including the first call?

Draw a separate branch for each call, even when two calls use the same argument.
Reveal answer
Return value: 4. Each grow(2) returns 2. Total calls: 7 = 1 call with n = 3, 2 calls with n = 2, and 4 base-case calls with n = 1.
Recursion · Comparison

Iteration and recursion both repeat work

Iterative sum

public static int sumToLoop(int n) {
    int total = 0;
    for (int k = 1; k <= n; k++) {
        total += k;
    }
    return total;
}

Recursive sum

public static int sumTo(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sumTo(n - 1);
}
For n ≥ 0, both return the same sum. The loop tracks progress in k and total. Recursion tracks progress through parameters and waiting calls. General conversions may require an explicit stack.
Final check

Three ideas to explain without running code

  1. Why can x > 0 && y / x > 2 safely handle x = 0?
  2. How many times does for (int i = 2; i <= 14; i += 4) run?
  3. If a recursive method prints only after its recursive call, when do those print statements execute?
Reveal answer
  1. The first condition is false, so Java skips the division.
  2. 4 times, with i = 2, 6, 10, 14.
  3. As calls return from the base case, beginning with the deepest waiting call.
Study checklist

What you should be able to do

  • Evaluate Boolean expressions and apply De Morgan’s laws.
  • Trace independent, chained, and nested decisions.
  • Explain short-circuit evaluation.
  • Write and trace while and for loops.
  • Use counters, accumulators, and digit algorithms.
  • Traverse and build Strings safely.
  • Count nested-loop operations and compare growth.
  • Trace recursive calls, returns, and output.
When checking an algorithm, try a boundary value, a typical value, and an input that makes the body run zero times.
